# 下載後處理

處理下載資料夾（`%USERPROFILE%\Downloads`）裡的影片：合併影像和聲音、找出舊剪輯在新版本裡的位置、轉成 AV1。

典型流程：下載 `.mp4` + `.m4a` → [合併](#合併merge_video) 成 `.mkv` →（有舊剪輯時先 [比對](#比對片段match_clip)）→ [轉檔](#轉檔convert_video)，轉檔時可以用 [轉檔進度](#轉檔進度watch_progress) 看還剩多久。

全部從專案根目錄執行，例如 `python -m download_processing.convert_video 黑名單 25`。

## 關鍵字

合併、比對、轉檔都用關鍵字在下載資料夾找檔案：用空白分詞，每個詞檔名裡都要有，不分大小寫、不分簡繁、不限順序。例如繁體 `黑名單` 對得到簡體 `《黑名单》`，`黑名單 16 12` 對得到 `黑名單.CUT.00'16-03'12.mkv`。找到的檔案數量不對時列出符合的檔案並結束（exit code 2），可以改用參數直接指定檔案。

## 合併：merge_video

把同名的影片 `.mp4` 和聲音 `.m4a` 用 mkvmerge 合併成 `.mkv`。需要 [MKVToolNix](https://mkvtoolnix.download/)（放在 `E:\Programs\MKVToolNix_102.0\`）。

```
python -m download_processing.merge_video <關鍵字> [--input <檔案>] [--overwrite]
python -m download_processing.merge_video "黑名单 focus"
```

- **關鍵字**：找出對應的那一組；多組符合時可用 `--input` 指定其中一組的 mp4 或 m4a。輸出檔名也用關鍵字：`下載\<關鍵字>.mkv`。
- **先檢查下載是否完整**，有問題就刪掉不完整的那個檔案並中止，重新下載後再跑：
  - 檔案結構：MP4 由一個個區塊組成，最後一個區塊不完整代表下載中斷在區塊中間。
  - 資料長度：檔頭記的總長度跟實際資料的最後時間差超過 0.5 秒，代表下載剛好中斷在片段邊界。
  - 兩者都完整但影片跟聲音長度差超過 1 秒時，不刪任何檔案，只提示（可能不是同一組）。
  - 旁邊還有 `.crdownload` / `.part` 檔（還在下載）時不處理。
- 合併以 `<關鍵字>.merging.mkv` 暫存，確認 mkv 裡影像和聲音的封包數都跟原檔相同，才改名並**刪除原本的 mp4 和 m4a**。輸出檔已存在時不覆蓋（exit code 3），加 `--overwrite` 才覆蓋。

## 比對片段：match_clip

找出一段剪過的影片（參考，例如舊的剪輯）在另一個同內容影片（目標，例如新下載的高畫質版）裡的哪一段，算出把目標剪成一樣所需的去頭去尾長度。

```
python -m download_processing.match_clip <關鍵字>
python -m download_processing.match_clip --reference <參考檔> --target <目標檔>
python -m download_processing.match_clip 姜杉
```

- **關鍵字**：要剛好找到兩部影片（任何副檔名），較短的當參考、較長的當目標。
- **比法**：兩部都用 ffmpeg 以較高的那個影格率（最多 60）取樣，每格縮成 16×16 灰階，扣掉亮度、對比的差異後比相似度，所以解析度、碼率、編碼不同都沒關係，但裁切、鏡像、加字幕或浮水印就比不到。先每 0.25 秒取參考的一格找目標裡最像的一格，投票出時間差，再逐格比對，相似度 0.9 以上算吻合，精確到一格。實測 4 分 13 秒的 1080p 目標約 12 秒（花在解碼）。
- **輸出**：每段吻合的範圍 `match: reference 0:00-0:43.1 = target 0:08.967-0:52.066`；參考有部分在目標裡找不到時印 `not found:`。參考剛好是目標的一整段時，印出轉檔用的 `trim: --trim-start 0:08.967 --trim-end 3:21.356`，可以直接加在轉檔指令後面。

## 轉檔：convert_video

把合併好的 mkv 用指定的平均位元率轉成 AV1。需要 [HandBrakeCLI](https://handbrake.fr/downloads2.php)（裝在 `C:\Program Files\HandBrake\`）。

```
python -m download_processing.convert_video <名稱> [<條件> ...] <位元率縮寫> [--input <檔案>]
                                             [--trim-start <長度>] [--trim-end <長度>] [--overwrite]
python -m download_processing.convert_video 黑名單 16 12 25
python -m download_processing.convert_video 公演 25 --trim-start 2s --trim-end 3s
```

- **名稱 + 條件**：名稱和條件合起來當關鍵字，找下載資料夾中的 `.mkv`；多筆符合時可用 `--input` 指定其中一個。輸出檔名用名稱：`下載\<名稱>.mp4`，已存在時自動加編號 `<名稱> (2).mp4`、`<名稱> (3).mp4`……，不動到舊檔。
- **轉檔前刪除其他試剪版本**：下載資料夾中符合名稱、但不符合全部條件的其他 `.mkv` 會被刪除，例如上例會刪掉 `黑名單.mkv` 和 `黑名單.CUT.00'13-03'12.mkv`。多筆符合時不刪任何檔案。
- **去頭去尾**：`--trim-start` 從開頭裁掉多少、`--trim-end` 從結尾裁掉多少，寫法可以是 `2`、`2s`、`1.5s` 或 `1:05`（分:秒）。腳本讀來源長度換算成 HandBrake 的 `--start-at` / `--stop-at`（後者是從起點算的長度，不是結束時間），印出保留的範圍。影像重新編碼，所以能剪在任一畫格（實測起點可能早一格，約 0.03 秒）；音訊照樣直接複製，從最接近的封包開始和結束。裁掉的總長超過影片長度時報錯，不刪任何檔案。
- **位元率縮寫**：對照 [bitrates.txt](bitrates.txt) 換成影像平均位元率，例如 `2` = 2048 kbps、`3` = 3072 kbps；新增常用位元率就在檔案加一行 `縮寫 = kbps`。不在檔案裡的縮寫會列出可用選項並結束。後面加 `fast`（例如 `t = 256 fast`）是試看用的快速轉檔：只跑一趟（`--no-multi-pass`）、SVT-AV1 速度 preset 10（HandBrake 1.11 最快的一檔），實測 1 分 23 秒的 1080p 從 98 秒降到 21 秒；只跑一趟時實際碼率會比目標低一些（192 → 151 kbps）。其餘設定（SVT-AV1 10-bit、preset 6、tune vq、多次編碼、MP4）都取自 HandBrake 圖形介面的自訂 Preset `AV1 2560`，只換掉位元率；要改其他設定就在圖形介面改這個 Preset。
- **音軌**：這個 Preset 不會自動選音軌，腳本會加上參數保留全部音軌（AAC 直接複製），轉完會逐一比對每條音軌每個封包的 MD5 跟來源完全相同（有去頭去尾時則要是來源的封包、依原本順序，中間最多允許少掉 10 個：HandBrake 用 `--start-at` 時偶爾會丟掉一個音訊封包，實測 3 分鐘的影片在結尾前丟了一個 21 毫秒的封包，有少掉時會印出在來源的哪個時間點；重新編碼的封包 MD5 不可能跟來源相同，所以仍能確認沒被重新編碼；開頭時間為負、播放時本來就丟掉的預熱封包可以少掉，HandBrake 從 MP4 複製時會省略、從 MKV 複製時會保留）。來源音訊不是 AAC 時 HandBrake 會轉成 AAC，此時會報錯。
- 加 `--overwrite` 時直接覆蓋 `<名稱>.mp4`，不加編號。轉檔中途以 `<輸出檔名>.converting.mp4` 暫存，成功才改名。
- 轉完印出來源與輸出的影像碼率、編碼、大小、長度。

## 轉檔進度：watch_progress

在 Claude Code 背景執行轉檔時，讀取轉檔的輸出檔，定時印一行進度，例如 `第 1/2 趟 35%，全部約剩 6 分`，給 Monitor 轉成通知。

```
python -m download_processing.watch_progress <轉檔輸出檔>
```

- **剩餘時間**：單趟或第 2 趟（最後一趟）直接用 HandBrakeCLI 的 ETA。第 1 趟的 ETA 只算這一趟，所以改用第 1 趟的速度推算：從第一次看到第 1 趟進度起，量至少 10 秒、進度至少增加 1%，用「花的時間 ÷ 增加的進度」推算第 1 趟總長，再假設第 2 趟要花 2.7 倍。從第一次看到進度才開始量，是為了不把轉檔前 probe、scan 的時間算進去。這個倍數是在這台電腦用 `AV1 2560` 實測的：第 1 趟約 85 fps，第 2 趟約 31 fps。
- **回報時機**：每 5 秒看一次輸出檔。算得出剩餘時間就馬上第一次回報（單趟通常 10 秒內，兩趟約 15 秒）；轉檔開始 30 秒還算不出來，也先回報一次「還算不出剩多久」。之後剩不到 10 分鐘時每 2 分鐘回報一次，不到 1 小時時每 5 分鐘一次，更久則每 10 分鐘一次；還算不出剩多久時，每 1 分鐘一次，算得出來就馬上回報。
- 輸出檔最後出現 `[exited with code`（Claude Code 在背景指令結束時加上）就安靜結束；超過 10 分鐘沒有新輸出時，印出可能卡住的訊息並結束（exit code 1）。
