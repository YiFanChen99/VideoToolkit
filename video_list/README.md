# 影片清單

把常用資料夾（含子資料夾）裡所有影片的影像碼率、編碼、解析度、檔案大小與長度整理成一份 Google 試算表清單，並且可以長期維護：每次執行只處理新增或有變動的影片，你自己加的狀態和標籤欄都會保留。

```
python -m video_list.list_video_info [<資料夾名稱> ...] [--spreadsheet <試算表 ID>]
python -m video_list.list_video_info            # 掃描 folders.txt 裡的全部資料夾
python -m video_list.list_video_info 舞蹈 MV     # 只掃描這兩個
```

從專案根目錄執行。

- **資料夾**：寫在 `folders.txt`，一行一個 `名稱 = 路徑`，`#` 開頭是註解。第一次使用時把 [folders.example.txt](folders.example.txt) 複製成 `folders.txt` 再改；`folders.txt` 列的是自己的影片庫，不進 repo。名稱會寫進清單的「資料夾」欄。不在檔案裡的名稱會列出可用的選項並結束。
- **清單**：Google 試算表的「影片」工作表，預設是腳本裡 `SPREADSHEET_ID` 那一份（網址 `/d/` 和 `/edit` 中間那一段）。工作表要先建好；空白的工作表會建好標題列，凍結標題列和檔名欄，在腳本的欄位後面留一個 10px 寬的空白欄做區隔，再建一個「狀態」欄。**執行時試算表可以開著**，也可以繼續編輯、排序。

## 需求

- [gspread](https://pypi.org/project/gspread/)：讀寫 Google 試算表（`pip install -r requirements.txt` 已包含）
- Google Cloud 的 service account（設定一次，見下方）

### service account

腳本用 service account 這個「機器人帳號」讀寫試算表，不用登入你的 Google 帳號。用個人 gmail 帳號設定（公司的 Workspace 帳號通常不能建金鑰）；免費，不用綁帳單。

1. 在 [Google Cloud Console](https://console.cloud.google.com/) 新增專案，到「API 和服務」→「程式庫」啟用 **Google Sheets API**。
2. 「IAM 與管理」→「服務帳戶」→「建立服務帳戶」，名稱自取，角色都跳過。
3. 點進它 →「金鑰」→「新增金鑰」→ JSON，把下載的檔案放到 `%APPDATA%\gspread\video-toolkit.json`（路徑是腳本裡的 `KEY_FILE`）。這個檔案等同試算表的讀寫權限，不要放進任何 repo 或分享出去。
4. 在試算表按「共用」，貼上服務帳戶的電子郵件（列表上就看得到，`….iam.gserviceaccount.com`），權限選**編輯者**，取消勾選「通知對象」。

用量遠低於 Sheets API 的限制（讀、寫各每分鐘 60 次）：每次執行讀 1 次，之後每次存檔讀 1 次、寫 1–2 次。

## 欄位

腳本只寫入以下欄位，靠第 1 列的標題找欄位，所以欄位可以任意調整順序：

| 欄位 | 內容 |
|---|---|
| 檔名 | 相對於該資料夾的路徑，不含副檔名，例如 `子資料夾/xxx` |
| 資料夾 | folders.txt 裡的名稱 |
| 副檔名 | 小寫，例如 `mp4` |
| kbps(影像碼率) | 只算影像、不含聲音：加總影像串流所有封包的大小，再除以影像長度。每種容器都用同一套算法，不採用檔案自己記錄的值（mkv、flv 的記錄不一定準） |
| 編碼 | ffprobe 的編碼名稱，HEVC 寫成 `h265`，其餘照原名，例如 `h264`、`av1`、`vp6f` |
| 寬、高 | 影片顯示時的解析度，例如 `1920`、`1080`；手機拍的影片如果是以旋轉 90° 的方式存檔，會換成直向的寬高 |
| 大小(MB) | 整個檔案，1 MB = 1,000,000 bytes |
| 長度 | 整個檔案，時間值，顯示成 `時:分:秒` |
| 修改時間、位元組 | 檔案的修改時間和精確大小，用來判斷檔案有沒有變，可以隱藏這兩欄 |
| Diff | 沒事時留空；`新增`：新加進來的影片；`更新`：內容變了，或搬移、改名了。這兩種會一直留著，看過後自己清掉（還沒清掉的 `新增` 檔案又變了，仍是 `新增`）。`已不存在`：掃描時找不到這個檔案；`讀取失敗`：ffprobe 讀不了（例如壞檔）。篩選時取消勾選 `已不存在`，就只剩實際還在的影片 |

**格式**：新加的列整列套用它上一列的格式（數字格式、字型、顏色、下拉選單），所以在試算表裡改整欄的格式，新列也會跟著用。腳本只寫值，不改既有儲存格的格式。

**其他欄位都是你的**，腳本不會改，例如「狀態」欄填 `隱藏` 再用篩選藏起來，標籤欄就在後面自己加，例如「類型」、「評價」。一個面向用一欄，篩選時每欄都是乾淨的勾選清單；同一欄要填多個值時寫成 `演唱會, 公演`，篩選用「包含…」。

## 每次執行做的事

- **沒變的影片**（大小和修改時間都相同）：不跑 ffprobe，整列不動。
- **新影片**：加在清單最後面，在 Diff 標成 `新增`，要排序就在試算表裡排。
- **同名但內容變了**（大小或修改時間不同）：重新 probe，只更新腳本的欄位，在 Diff 標成 `更新`。
- **不見的影片**：不刪那一列，在 Diff 標成 `已不存在`，標籤保留。之後檔案又回來，就清掉這個標記。
- **Diff 欄被隱藏**：掃描完成後會取消隱藏，讓這次留下的標記看得到（中斷時不動）。
- **搬移或改名**：新影片的大小和修改時間跟某一筆不見的影片完全相同（而且只有一筆）時，認定是同一個檔案，沿用那一列和你的標籤，只改資料夾、檔名、副檔名，不重新 probe，在 Diff 標成 `更新`。跨資料夾搬移也一樣；folders.txt 裡的名稱改掉了，舊名稱的列也會這樣認回來。
- **讀取失敗的影片**：每次都會重試（失敗得很快，不花時間）。
- **沒有寬高的舊列**（在加上寬、高欄之前就量好的影片）：只讀檔頭補上寬高，不重新計算碼率；487 部約 17–24 秒。
- **找不到的資料夾**（例如外接硬碟沒接上）：略過，該資料夾的列完全不動，不會被標成 `已不存在`。只掃描部分資料夾時，其他資料夾的列也不動。

花時間的只有 probe：計算碼率要讀過整個檔案，大檔案在 HDD 上要十幾秒。讀寫試算表本身很快：一開始讀整張表約 1.5 秒（含連線），每次存檔約 0.5–1 秒，沒有影片要 probe 時整次執行約 2 秒。腳本每 60 秒存檔一次，按 Ctrl+C 中斷時也會先存檔，下次執行會從還沒做完的影片接著做；存檔失敗（例如網路斷了）會印出原因、繼續 probe，下次存檔再寫。

結束時印出這次新增、內容變了、搬移或改名、重新出現、已不存在、讀取失敗的影片，和試算表的網址。

## 在試算表裡編輯時要注意

- **執行中可以排序、插入、刪除列**：腳本存檔前會重讀整張表，用「資料夾＋檔名＋副檔名」找回每部影片現在在哪一列，所以值不會寫錯列。執行中被刪掉、或手動改了資料夾／檔名／副檔名的列，這次的結果不寫入，結束前會列出來。
- 執行中不要改腳本欄位的標題（例如把「Diff」改名），存檔時找不到會停下，還沒存的結果不會寫入。
- 腳本寫入時不轉換內容，`0.MV`、`20230329` 這種檔名會維持文字，不會變成數字或日期。
- 新加的列在最後面；篩選範圍不夠時會延伸到最後一列，篩選條件和排序設定保留。

掃描的副檔名：`.mp4 .mkv .flv .avi .mov .wmv .webm .ts .m4v`。
